# Validation scope

Validation results must identify the execution boundary. A passing unit test
does not establish that a package installs or that a user's gateway accepts the
same requests.

## Test layers

| Layer | What it establishes | What it does not establish |
| --- | --- | --- |
| Unit tests | A function or component behaves as tested with controlled data. | Network service compatibility or packaged command behavior. |
| Local integration tests | Trident sends real HTTP requests to a controlled local server and handles responses. | Compatibility with an external provider or its retention controls. |
| Installed-wheel tests | A clean environment installs and runs the built CLI artifact. | Performance or coverage on all operating systems and gateways. |
| Full scan workflow | Scanner/import, Council, judge, Red-Team, triage, report, and exit status work for the supplied fixture. | Universal vulnerability detection or exploitability. |
| External provider test | A named remote provider accepts the exercised operations and settings. | Other provider deployments, regions, plans, or retention behavior. |

The current custom endpoint acceptance uses a deterministic OpenAI-compatible
gateway under local control. Its request log verifies endpoint paths, model
aliases, auth-header presence, and request order. This is gateway integration
evidence, not an external-provider test.

## Reproduce local checks

From `backend/` in a development environment:

```bash
python -m pytest
python -m ruff check trident tests
python -m compileall -q trident
python -m build --wheel --sdist
python -m twine check dist/*
```

Release evidence should also identify the installed wheel filename and hash,
environment, CLI commands, standard output, standard error, exit codes,
reports, and sanitized gateway log. Do not reconstruct terminal output.

## Review the evidence

For each installed scan, compare terminal P0-P4, Total, Untriaged, and
Unresolved counts with JSON generated by that same job. Confirm disposition
filtering, unique finding IDs, JSON/SARIF schema, and the expected exit code.
For gateway tests, confirm the HTTP request log shows the configured URL path,
model alias, and expected auth presence without retaining credential values.

An empty prioritized total is not evidence that every candidate was disproved.
Check unresolved, untriaged, and non-actionable disposition counts. Review
security-scan output finding by finding and report unavailable tools as
unverified, not passed.

## Evidence boundary

Test fixtures and local gateways use synthetic source, identifiers, hostnames,
and credentials. Live provider, customer, or production infrastructure is not
implied. Consult the release acceptance artifact for the exact test matrix and
its limitations.
